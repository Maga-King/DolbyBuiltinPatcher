# 电脑 1.0.6 / 手机 0.2.7：标准路径配置，无启动门控

模块版本：`0.6.2-standard-config-preview1`（614）。

旧版音频配置放在 `late/`，只在 `repair-ok` 和服务检查通过后单独 bind。
NoMount 可以通过 VFS 提供库文件而不产生传统挂载记录，导致补挂检查失败，
随后 DMS 未启动、音频配置也未发布。本版移除这条依赖链。

| 配置 | 模块 ZIP 路径 | 目标路径 |
| --- | --- | --- |
| ODM 音效 | `system/odm/etc/audio_effects_config.xml` | `/odm/etc/audio_effects_config.xml` |
| Codec2 音频 | `system/vendor/etc/media_codecs_c2_audio.xml` | `/vendor/etc/media_codecs_c2_audio.xml` |

其他实际发现的音效 XML、各 SKU 配置及 ODM 配置也使用相同的标准分区映射，
与库文件一起交给元模块加载，并进入 `mounts.tsv`、权限标签清单和 Action 文件检查。
不再生成 `late/`、`late.tsv`、`gate.sh`、`commit.sh`、`recover.sh` 或 `codec.sh`。

VINTF 仍在 early-init 从 metadata 加载，但现在一次性包含完整 Codec2/default9 声明，
不再二次发布或刷新 APEX 信息。early-boot 先有界修复数据库权限，再由 init 直接启动
HIDL DMS、AIDL DMS 和 Codec2；准备失败或超时也会继续执行后续 start。
移除补挂成功标记、特定音频 HAL 服务名、linker 检查和服务注册轮询等启动条件。
Codec2 的接口映射和进程退出后的 3 秒恢复间隔保留。

元模块的子挂载保存/恢复与缺失项补挂保持独立；NoMount 下缺少传统挂载记录时，
补挂可能停止，但不再阻止服务启动。本版不自动撤回音频配置。
原生 ROM 内置、数据库内容、App 数据保留逻辑不变。

验证：91 项 Windows Python/Android 适配器/真实 ZIP 导出测试通过；
6 项 Linux 数据库测试、37 项隔离挂载/补挂/子挂载恢复测试通过。
Debian GNU `cmp -s` 在 tmpfs 与 procfs 大小不同的场景会提前判不同，
Linux 挂载测试使用临时 PATH 中的 BusyBox `cmp`，与 KSU 运行工具一致；未改产品校验逻辑。
Windows GUI 冒烟测试通过，Android APK 签名与 0.2.6 一致。
NoMount 路径映射已对照其源码核实；尚未验证本版的真实开机、服务注册或播放效果。

更新生成器后重新生成、安装模块并完整重启。仅安装新版生成器不会改变旧模块。
切换元模块仍建议卸载杜比模块 → 完整重启 → 重新安装。
