# 电脑 1.0.3 / 手机 0.2.4：元模块 + 缺失项补挂

作者：科比。杜比 App/配套方案来源：LunarisDolby / AlphaDroid。
运行时版本：0.6.1-meta-repair-preview1（613），与本轮手机启动验证的包相同。
仅改变模块生成及其测试/说明；原生 ROM 内置逻辑、标签合并、事务和策略编译不变。

## 相比此前版本

恢复首个公开版本 e09bb23 的标准 system/ 单份载荷和 preserve 保存/恢复流程，追加同步、有界补挂。
不让元模块和完整自挂载同时争用一整套目录，不安装 files/ 第二套载荷，不正常设置 skip_mount。
门禁、数据库权限修复、App 同签名更新、Codec2 非 oneshot + 接口启动映射 + restart_period 3 保留。
不重启 HWS 或音频 HAL，不增加开机后轮询。切换元模块仍须卸载杜比 → 完整重启 → 重装。

## 为什么只验载荷不够

真实 Linux 挂载实验复现：元模块覆盖父目录后，杜比文件全对，但早期 VINTF 和原厂 OPEX 子挂载消失。
事后 rbind 镜像只会保留已经错误的可见树；仅重绑 VINTF 也不能恢复 OPEX。
所以必须挂载前保存、挂载后恢复，再检查/补挂，不能把“82/82”当成所有原厂组件正常。

## 测试矩阵

| 场景 | 本次结果 |
| --- | --- |
| 纯元模块全部挂齐 | 不添加补挂层 |
| 纯元模块缺少一个文件/新增目录 | 补齐；保留 OEM 子挂载 |
| 补挂前其他模块覆盖同名文件 | 恢复所需杜比内容 |
| 内容正确但权限错误 | 检出并补挂 |
| 内容正确但 SELinux 标签错误 | 手机 Enforcing 实测检出并补挂 |
| VINTF 被父目录覆盖、OPEX 同时被遮住 | 保存/恢复同时恢复两者；只重绑 VINTF 的对照仍丢 OPEX |
| 多层 OverlayFS 到达内核上限 | WSL 中第 3 层失败；保留已有两层仍能补挂，不新增 overlay 超级块 |
| 模块 system/vendor 被安装器移动并通过链接引用 | 在模块目录内正确解析来源 |
| 载荷暂存 bind 失败 | 限额复制到私有 tmpfs 后发布 |
| 只读处理失败 | 撤回自己的挂载，不卸载元模块共享父层 |
| 原系统子挂载恰好占了同一杜比文件路径 | 保守拒绝并撤回，不静默破坏原子挂载 |
| 元模块完全没挂 / 零项正确载荷 | 拒绝整包自挂载，不提交音效 |
| 音频已启动 / 模块禁用 | 拒绝迟到接入 |
| 重复执行补挂 | 不堆叠重复挂载 |
| 链接/类型冲突、重叠目标 | 停止，不穿越链接写入 |
| 补挂后外部模块再次挂同一路径 | 一次性补挂无法阻止；回退不会卸载后来者 |
| horae、Android `[` 命令链接等历史案例 | 缩小到必要父目录，保留合法旁支；异常路径拒绝 |

测试数：88 项 Python 回归；17 项补挂流程 + 3 项父/子挂载对照 + 17 项挂载引擎 = 37 项 Linux 测试；8 项 Android 实机隔离测试。
测试数据都是合成文件，不是故意破坏真实系统库的“冲突刷机包”。不上传用户日志、数据库或 ROM。

## 真机范围

PLQ110 主系统 / Android 17 / SELinux Enforcing / Mountify 2.0.3：

- 实际模块启动通过，82/82 项直接挂齐，repair=0。
- HIDL DMS、AIDL DMS、Codec2 default9 注册，AC3/EAC3/JOC/AC4 列表可见。
- 单独在私有挂载命名空间验证：全齐、覆盖一项、错权限、错标签、缺目录、迟到、无元模块、空元模块八种情况。
- Android 测试适配了测试路径、命名空间判定和只读 getprop 模拟；未改变真实系统属性或全局 SELinux。
- 实际设备挂载/标签检查保持启用。init 命名空间没有测试挂载，测试目录已清理。

这不等于全机型开机验证；未在真实开机中刷入破坏性冲突模块。其他元模块/KSU 分支仍需分别实测。
服务就绪不等于实际解码/音效全生效：本轮 com.salt.music 活动输出没有 DAP 链，DAP 在另一待机输出。
本次没有改这个播放路由，也不把它解释成正常设计限制。

## 本轮其他故障不是补挂能修复的

- 主系统 metadata 的旧 initrc 注入可能跨入 DSU，与已内置的 Dolby VINTF 重复；禁用并清理旧注入后用户反馈可启动。当前没有自动跨 DSU 隔离。
- 另一份 PJZ110 DSU 日志是 com.heytap.mcs 与 android.uid.system 签名不匹配，system_server 连续崩溃。不能用补挂或去掉签名检查掩盖；要检查 APK/ROM 来源。
- 数据库权限、App 数据标签、Codec2 恢复映射有回归保护，但不是本次故障注入的音频实播测试。

## 复现

```sh
python -m unittest tests test_mobile -v
sudo python3 test_meta_repair_linux.py
sudo python3 test_meta_preservation_linux.py
sudo python3 test_mount_linux.py
```

真机测试需明确设备和授权，仅专用临时目录，绝不自动选设备、安装模块或重启：

```sh
python test_meta_repair_android.py --serial YOUR_SERIAL --adb /path/to/adb
```

挂载测试使用 root 和私有命名空间；不要在不理解命令的环境下改成公共命名空间运行。
