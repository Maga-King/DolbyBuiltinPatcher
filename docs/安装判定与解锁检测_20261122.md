# 模块安装返回与 ColorOS 用户状态修订

证据：Downloads/KernelSU_module_action_log_2026-11-22-21-17-13.log，ColorOS PJZ110_17.0.1.202、SDK37、DSU0。
PackageManager 已注册用户0的 /data/app 更新应用，versionCode8、privileged/system_ext、installed=true、stopped=false；
安装脚本仍因 Failed transaction (2147483646) 返回1直接报失败。此证据说明包当前已注册，
不能证明当次报错的安装事务确实提交；修订以未来每次操作的注册路径和 APK 原文验证结果为准。

新增 package-state.sh：保留pm install返回码与原始输出，不直接||exit；
最多三次、每次3秒查询用户0路径，要求真实 /data/app 文件且与模块APK字节相同。
核对通过才将异常返回改为成功；没有包、不同包、系统挂载或查询持续失败都仍报未确认。
不卸载、不降级、不清设置；label/777修复在确认后继续执行。

同一日志用户解锁返回 Unknown command: is-user-unlocked，而 DE 已777、CE仍0700、
没有storage-after-unlock.log。旧脚本因此漏掉首次解锁后的权限准备。
新增 user-state.sh 优先读 ActivityManager get-started-user-state 0，再兼容原cmd user查询；
不支持时明确unknown，使用原有有界启动等待，随后退出，不增加常驻轮询。

详细诊断增加命令/查询日志、过滤ColorOS推荐/排序噪声，DAP展示改为匹配附近上下文，
不会因前32条线程名占满而隐藏DAP。完整音频资料仍在diagnostic-detail。

仍需单独证据：日志发现 /odm/etc/audio_effects_config.xml 与模块原文不一致，
以及 initrc cache无法核验；当前三项服务全部running/registered。
此次不擅自覆盖未知音效XML或重启任何服务；实际效果和下次启动缓存仍需完整文件/日志。

验证：106项主测试、4项WSL执行fixture通过；覆盖成功、提交后异常返回、
错误APK、无包、仅系统挂载、查询失败、ColorOS不支持命令/锁定/未知回退；修改Shell通过ShellCheck。
原生ROM流程未改，不操作手机。回退使用上一版生成器及模块；原设置文件不删除。
