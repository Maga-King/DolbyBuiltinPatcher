## preview3 / APK 0.1.4

安装时限时尝试同签名 `pm install -r --user 0`，保留模块系统底包，不清数据、不强制降级、不授予 Root、不修改隐藏配置。开机完成后有一次有界补试；相同 data/app APK 跳过安装。首次尚无系统底包时可能暂为用户 App，重启扫描底包后须确认 SYSTEM/PRIVILEGED、隐藏接口和真实参数读写，不能仅凭安装成功宣称全部功能可用。签名冲突/高版本拒装留日志，不自动卸载旧版。只处理主用户；多用户不保证。

主挂载仍是递归 bind 合并目录，备用路径是单个资产 bind/只读 remount 失败后先撤销该暂存叶子，再复制到私有 tmpfs，校验内容与权限标签，最终以只读目录发布。累计复制最多 128 MiB，并要求至少 256 MiB MemAvailable 余量；不够则停止。目录发布失败、未知挂载归属、命名空间不对不会改用 OverlayFS 强接管，不绕过原有开机门控。该备用方案只覆盖叶子 bind 失败，不覆盖整个 mount 系统不可用。

不通过伪装挂载名逃避卸载；系统/音频侧仍使用 KSU 挂载，APK 更新路径用于降低应用资源被卸载的影响。不能保证全部 Zygisk/VFS 实现兼容或任何机型绝不卡启动。卸载模块后 data/app 更新和用户数据保留，由用户自行卸载，避免误删原有同包应用。

2026-09-28 PLQ110 实测：同签名更新后 codePath 位于 data/app，SYSTEM / UPDATED_SYSTEM_APP / PRIVILEGED、usesNonSdkApi 及音频权限保留，进程仍为 priv_app_36，Activity 启动成功，桌面及杜比进程均能读取实际 APK。重复执行跳过安装。HIDL / AIDL DMS / Codec2 仍 running；这不代表全部参数及实际解码已验证。当前手机仅新增安装助手并安装 App 更新，没有替换正式挂载引擎、没有重启验证 preview3 全套启动。

修复安装输出句柄问题：PM shell 命令会把标准输出/错误 FD 传给 system_server；当前设备直接传入模块标签的日志 FD 会报 Binder EPERM。改用管道传输、tee 写模块日志，pipefail 保留失败码，不新增 SELinux 放权。

随后用户反馈调参“好像没问题”；有限近期日志未匹配到调参、APK 资源加载或 Java 崩溃错误，三个服务仍 running。属于初步验证，不是全参数或长时间播放验收。

复制兜底通过 Android Enforcing 私有命名空间故障注入：故意拒绝 bind，复制实际 54 MB APK，内容/标签/权限一致，发布只读，init 命名空间未改变；临时挂载及脚本已清理。另通过 62 项 Python 回归与 10 项 Linux 挂载测试。未验证所有隐藏实现、首次安装后系统身份升级、完整开机和实际播放。

状态：2026-09-28，本地预览，**未完成 Android 真机验证，不代表全兼容**。仅修改模块生成路线；原生 ROM 内置的补丁、策略编译和写回不变。

## 实现与边界

杜比资产位于 `files/`，不再输出顶层 `system/`。`skip_mount` / `skip_mountify` 是主动防重复标记，不是挂载失败。支持同步 `post-mount` 的 KSU 完成元模块阶段后，杜比独立构建合并目录并递归 bind。未修改目录递归保留原有子挂载，修改分支逐级合并，保留其他文件，不 remount 实体分区为可写。

自挂载有 25 秒执行预算和 3 秒终止宽限；正常失败/TERM 只按本次记录的挂载 ID 撤回，不卸载已经被他人替换的挂载。内核不可中断阻塞、强制杀死和断电不受 shell 清理保证。启动门控要求本次成功标记及 init 命名空间内容验证；迟到或失败不提交杜比音频配置，不杀 HWS、不重启音频服务。

不复制任何元模块的完整挂载引擎，不加载 LKM，不调用其 VFS 写接口，不改全局应用排除名单。该设计减少对元模块的依赖，不等于能纠正内核挂载隐藏、VFS 重定向、应用隔离或 SELinux 的所有问题。

**切换元模块后，请卸载本模块 → 重启 → 重新安装。** 不在同一次启动里依靠卸载撤销已经存在的 bind。更换 ROM 后重新生成。

## 为什么仍用 metadata

[KSU 内核源码](https://github.com/tiann/KernelSU/blob/08a3b087e49227c8a6731c5f1114998b5e25255b/kernel/runtime/ksud_integration.c) 只尝试 `/metadata/watchdog/ksu/modules.rc` 与 `/metadata/ksu/modules.rc`。本次查看的 Next、SukiSU、ReSukiSU 也如此。watchdog 目录可选，早期可读的 metadata 路径是此路线前提。没有该路径要换启动机制或固化适配，不能仅迁移到 `/data/adb`。模块不自动修改 boot/vendor_boot、fstab 或系统 init。

## App 打不开 / 管理器 0 KB

管理器 `du` 失败后显示 0 和 APK 的真实长度为 0 是两回事。Action 一次性检查文件大小、标签、init 可见性、PackageManager 注册、当前 App 进程视图、服务注册及有限相关日志。不存在 App 进程就明确报告未检查该命名空间，不强行启动应用。

杜比 App 不需要 Root。仅在用户确认时为 `org.lunaris.dolby` 关闭应用级“卸载模块”，并检查各隐藏工具的 UID 排除；不要为此关闭全局隐藏。当前各 KSU 分支的 profile 权限不统一，本模块只读查询，不假冒管理器、不盲写配置、不授予 App Root。

Action 最多约 47 秒，仅保留 `.runtime/diagnostic-last.txt`，没有常驻检测。诊断不等于播放测试；HIDL、AIDL、Codec2 注册不证明正在进行 E-AC-3/AC-4 解码。

## 已做的验证

Python 回归；Linux 私有挂载命名空间中的目录合并、原有子挂载保留、修改分支下的子挂载、只读替换、符号链接冲突拒绝、挂载 ID 归属检查与撤回。脚本为 `test_mount_linux.py`。这些测试不覆盖 Android SELinux、KSU 实际启动顺序、内核隐藏或 App 扫描；测试版需另外实机验证。

### preview2 / APK 0.1.3 修复记录

2026-09-28，PLQ110 / Android 17 / Enforcing / ksud 3.3.0 + Mountify：preview1 在 `/vendor/bin` 合并阶段失败，尚未发布任何杜比目录；门控释放原厂音频。根因是严格字符白名单误拒绝合法的 `/vendor/bin/[`（指向 toybox_vendor）。修为拒绝路径穿越和当前日志不能编码的形式，不再把合法标点当作命令注入。

另在设备隔离空间发现 BusyBox 单参数只读 remount 报 `can't find ... in /proc/mounts`，改为同时传入已知源、目标，不依赖该自动查找。补充原始目录保留/复制链接/只读 bind 的失败路径诊断。

新引擎在设备的 `unshare -m --propagation private` 中成功合并并发布 7 组目录，82 个杜比文件比对通过，`[` 链接保留；耗时约 13.2 秒，探针正常退出且 init 命名空间未出现测试挂载。此实验没有启动 Dolby HAL、没有改正式模块、没有重启，也不等于开机顺序、实际播放或后处理已验证。
