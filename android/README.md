# 手机版 0.2.4（元模块补挂测试版）

本版模块生成：以首个公开版本 `e09bb23` 的标准 `system/` 载荷及
挂载前保存/挂载后恢复子挂载流程为基础，追加有界的缺失项补挂。不再生成 `files/`
双份载荷或 `self-mount.sh`；没有有效元模块挂载时不自动接管整包。
电脑 1.0.3 已同步，Gradle 与电脑共用根目录模块后端及运行脚本，避免两份实现分叉。
原生 ROM 内置、事务、标签及编译逻辑未改；保留 0.2.3 的数据库与 App 修复。
PLQ110 Enforcing + Mountify 2.0.3 已开机及注册服务，82/82 项挂齐、补挂 0 次。
另有 37 项 Linux 挂载测试和 8 项手机 Enforcing 合成冲突测试；不是全机型或实际解码覆盖。
详见[验证范围与已知限制](../docs/元模块补挂验证_20260929.md)。

科比 · 基于 LunarisDolby 配套资产，Java + Chaquopy 调用与电脑端相同的补丁引擎。
ARM64，界面最低 Android 8；面向已支持的 ColorOS 17 音频结构，不是任意手机通用移植器。

## 三种操作

| 入口 | 输入 | 是否修改输入 |
| --- | --- | --- |
| 读取系统并生成模块 | 当前可见系统文件 | 否，只读；可能读到其他模块挂载 |
| 从此 ROM 生成模块 | 手动输入解包目录，例如 `/data/DNA/DNA_01` | 否，只生成 ZIP |
| 一键修改此 ROM | 同上，需要五分区目录及 DNA `config` | 是，先备份后事务写回 |

两种模块生成均用“保存模块 ZIP”导出，再自行交给 KSU 安装。
模块生成不按 SDK、机型、设备指纹拦截；会提示风险，不保证生成包可用。
原生 ROM 内置沿用电脑端结构要求及策略编译，不把模块 sepolicy.rule 当成系统预编译策略。
需解包同一套 ROM 的 system、system_ext、vendor、odm、product 五分区，并保留 DNA `config`；
不是直接选择 `.img` / `super.img`。最小范围挂载仅作用于生成模块，不改变原生内置流程。
不会自动刷分区、刷模块或重启，没有后台服务、开机广播、网络权限或常驻轮询。

## ROM 修改与恢复

0.2.2 修复的是本工具的原厂文件标签保留：修改已有文件默认读取 DNA `config` 中的唯一标签，
兼容分区槽名、system/system 前缀和旧转义格式；缺失或冲突时拒绝猜默认标签。新增杜比资产显式标签不变。
已处理的 ROM 须先回退原任务再重做，升级 APK 本身不修改 ROM，也不抹掉旧记录。

1. 填写真实解包目录。拒绝系统运行分区及应用/系统数据目录，不接受分区镜像文件。
2. 确认后只读快照，在 App 私有目录完成合并 XML、VINTF、RC、文件标签与打包元数据。
3. 使用随 APK 提供的 ARM64 secilc 编译目标普通/调试策略，沿用电脑端基线验证、必要规则与扩展规则流程。
   保留原厂规则、neverallow 忽略配置和宽规则；编译失败时不写回 ROM。
4. 生成清单与备份后，复用电脑端一次性事务：写前检查、逐文件记录、失败回退。
5. 手机备份在 **ROM 同级 `.dolby-patcher-backups/<目录名>-<任务号>`**；App 私有 `files/history` 保存构建记录。

构建阶段可取消；进入写回/回退阶段不强杀事务。请保持前台。
意外退出后输入原路径，先点“查询 / 恢复上次事务状态”，不要直接重试修改。
这是重新查询已有一次性事务，不是强行修复所有中断；`recovery-required` 需要保留备份人工处理。
“回退此 ROM 的上次修改”只恢复本应用该路径最近一次记录，不覆盖被其他工具进一步修改的文件。
**卸载 App 会丢失私有记录；外部备份仍保留。确认打包前不要卸载或清数据、移动 ROM、删除备份。**

## 清理按钮

- **清理无用缓存**：删除读取快照和成功模块构建的中间文件；保留生成 ZIP、原文件备份及回退记录。
- **删除此 ROM 的备份与记录**：二次确认后，只删除本应用对所填目录创建的已结束事务备份和构建记录。
  不删除 ROM，不按通配符清空备份父目录，也不处理其他工具的备份。删除不可恢复，会失去对应回退能力。
- 有未决或不明状态事务时，两种清理均拒绝执行，先查询/处理状态。

## 模块同步修复

0.2.3 使用的 `0.6.1-selfmount-preview6` 曾加入以下修复；0.2.4 保留数据修复，但挂载方案以上文为准：
在 DMS 启动前修复现有数据库及 WAL/SHM/journal 的属主、权限和标签，
不删除或重建数据库、不清预设、不改 App 数据属主、不新增轮询。原生 ROM 内置逻辑未改。
更新生成器后须重新生成并安装模块，才能应用修复；本次不修复免解锁环境或热重启的早期接入问题。
当前版本补挂已有文件使用独立 bind，新增文件仅合并最近已有父目录，不新增 OverlayFS；
保留子挂载、单文件 bind 的限额复制兜底，
同签名 App 更新安装与 priv-app 数据标签修复。Action 为中文只读诊断。
切换元模块后：卸载杜比模块 → 重启 → 重装。需要可用的早期 initrc 注入及早期可读的 `/metadata`；
`watchdog` 子目录不是必需项。没有接口的旧 SukiSU 不能强行跳过。
不杀 HWS，不重启音频 HAL，不添加 Zygisk 依赖或擅改隐藏设置。
详见[兼容说明](../docs/元模块与自挂载兼容说明.md)。

## 构建

JDK 17、Gradle 8.13、Android SDK 35、Python 3.12。ROM 内置另需 Android NDK 和构建期 flex。
Windows 可使用 WSL 的 flex，手机运行时不需要 WSL、ADB、电脑或 Windows 编译器。

在仓库根目录运行：

```powershell
# 仅构建 Android ARM64 策略编译器；不包含任何杜比资产。
.\native\build-android.ps1 -Ndk "C:/Android/Sdk/ndk/28.2.13676358"
gradle -p android :app:assembleDebug -PdolbyPrivateAssets="D:/我的私有杜比资产"
```

`libsecilc.so` 是由 NDK 编译的 PIE 可执行文件，采用 Android 8 / ARM64 ABI 与 16 KB 对齐，
由安装器解压到 nativeLibraryDir，再作为子进程运行，不尝试执行 App 可写数据目录内的二进制。
源码在 `third_party/selinux`，构建脚本在 `native/build-android.ps1`；许可证随 APK 资产保留。
公开源码构建缺少私有 `payload.zip` 时只能检查环境，不能完成杜比生成/内置；缺 ARM64 编译器不影响模块生成。
不要提交私有资产、APK/ZIP、设备日志或 local.properties。

## 验证边界

- 主机回归覆盖两种模块来源分流、只读限制、事务运输、取消、重复修改/未决事务拒绝、清理边界等。
- 自挂载有 Linux 私有命名空间测试，以及 PLQ110 的 Android 隔离挂载和 App 标签测试。
- 0.2.0 在 PLK110 / Android 17 / Enforcing 对隔离 ROM 快照运行原生 ARM64 编译、事务写入与回退；不写用户原 ROM、不重启。
- 测试副本保留补丁输入，其余库只保留名称清单，不能拿来打包刷机。
  流程测试通过不等于所有 ROM 打包或刷入成功，仍需目标设备验证。
